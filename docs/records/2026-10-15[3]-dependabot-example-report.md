# Dependabot и пример: почему `/example` снят с обновлений

> **Состояние на 2026-10-15:** сделано. Блок `/example` убран
> из `.github/dependabot.yml`, PR #44 закрыт.
> **Что это:** почему ни одно обновление Dependabot в `example/` не проходит
> ногу floor и почему ни правило `ignore`, ни точная версия этого не чинят.
> **Связанные записи:** `2026-10-15[1]-revival-report.md`.

## Что случилось

Первым же заходом после push Dependabot открыл PR #44: url_launcher 6.3.2 →
6.3.3 в `example/`. Нога floor в CI упала:
`url_launcher 6.3.3 requires SDK version ^3.11.0`.

## Откуда Dependabot берёт SDK

SDK для сборки Dependabot выбирает утилитой `infer_sdk_versions`
(dependabot-core, `pub/helpers/bin/infer_sdk_versions.dart`): она ставит
новейший релиз Flutter, который допускает `environment` в `pubspec.yaml`.
У примера там `sdk: ^3.6.0`, это любой Dart до 4.0, и Dependabot собирает
на Flutter 3.47 — на нём 6.3.3 подходит. Что `^3.6.0` здесь пол, он знать
не может. В закоммиченном lock стоит 6.3.2: это последняя версия для Dart 3.6
и Flutter 3.27, её собственный `environment` — ровно `^3.6.0` и `>=3.27.0`.

## Почему падает любое обновление, а не только это

Dependabot пересобирает lock целиком, вместе с пакетами, которые Flutter
прибивает к своей версии: в #44 сдвинулись 16 пакетов, среди них `test_api`
0.7.3 → 0.7.12 и `leak_tracker` 10.0.7 → 11.0.2. Проба 2026-10-15: lock из #44
с ограничением `^6.3.1` на Flutter 3.27.0. `pub get` откатывает все 16 пакетов
(`Changed 16 dependencies!`) и переписывает lock, а на этом шаг CI
`Nothing drifted` и упадёт. Так будет с любым обновлением в `/example`: lock,
собранный на 3.47, несёт точные версии `flutter_test` 3.47.

## Почему не помогает точная версия

Точная версия `url_launcher: 6.3.1` без `^` тоже не спасает. Dependabot берёт
из отчёта pub поле `singleBreaking`, а pub для него снимает с пакета
ограничение целиком (`lib/src/command/dependency_services.dart` на ревизии
`bdc44e6`, которую держит Dependabot). Точную версию pub по своему правилу
меняет на новую точную: PR был бы `6.3.1` → `6.3.3`, с тем же lock.

## Решение

Владелец выбрал 2026-10-15 убрать `/example` из `dependabot.yml` и закрыть #44.
Поднимать пол ради зависимости примера не стали: 6.3.3 требует Flutter 3.41,
а подъём пола — отдельный заход ради самого пакета. Правило `ignore` для
url_launcher дало бы то же самое: других обновлений у примера нет,
flutter_lints 5.0.0 — последний 5.x, а мажоры уже в `ignore`. Снятый блок
говорит об этом прямее, и причина записана комментарием в самом
`dependabot.yml`. Зависимости примера обновляются руками, когда поднимается
пол.

Ограничить `environment` примера полом, чтобы Dependabot собирал на 3.27,
нельзя: тогда откажется работать нога stable. Проба 2026-10-15,
`sdk: ">=3.6.0 <3.7.0"` и `flutter pub get` на 3.47.0:
`Because example requires SDK version >=3.6.0 <3.7.0, version solving failed.`

В корне lock не закоммичен, откатывать там нечего, и Dependabot для корня и для
GitHub Actions остался.

# Переименование ветки `master` в `main` на GitHub

> **Состояние на 2026-10-15:** сделано. `main` на GitHub — ветка
> по умолчанию, `master` заморожена на `6a90afb`, ветка запушена
> до `42af42d`.
> **Что это:** почему при переименовании оставлена `master` и чем это
> проверено.
> **Связанные записи:** `2026-10-15[1]-revival-report.md`.

## Задача

Владелец решил переименовать ветку `master` в `main`, как у соседей. Локально
ветка, CI, `AGENTS.md` и ссылки README были переведены на `main` коммитом
`8d3903d`. Оставалось переименовать ветку на GitHub и запушить.

## Чем грозило переименование

README 1.2.1 ссылается на 17 картинок адресами вида
`https://github.com/vi-k/bubble/blob/master/screenshots/<файл>?raw=true`
(восемнадцатая ссылка с тем же префиксом ведёт на папку `example`, это
страница). pub.dev показывает их через свой прокси `external-images.pub.dev`,
который ходит по этому адресу.

До переименования адрес отвечал цепочкой `blob/master/…?raw=true` →
`raw/refs/heads/master/…` → `raw.githubusercontent.com/…/refs/heads/master/…` →
`200 image/png`.

После переименования (`POST /repos/vi-k/bubble/branches/master/rename`) тот же
адрес с параметром против кеша отвечает:

```
HTTP/2 302  location: https://github.com/vi-k/bubble/blob/main/screenshots/example.png
HTTP/2 200  content-type: text/html; charset=utf-8
```

Редирект переименованной ветки теряет `?raw=true`, и вместо картинки приходит
страница. Так же это выглядело на dart-lang/sdk при разборе вариантов. Сам
`raw.githubusercontent.com/…/master/…` за переименованием следует и отдаёт PNG
даже мимо кеша (`x-cache: MISS`), ломается только редирект на github.com.

Ловушка проверки: первый запрос сразу после переименования, без параметра
против кеша, вернул PNG. Это был ответ из кеша github.com, а не поведение
ветки.

## Что сделано

Выбран второй из трёх вариантов, разобранных в handoff: переименовать и завести
замороженную `master`.

1. Ветка переименована запросом выше. GitHub сам перевёл PR #40 на `main`.
2. `master` создана заново на `6a90afb` (1.2.1, тег `1.2.1`):
   `POST /repos/vi-k/bubble/git/refs`. Ссылка `blob/master/…` теперь находит
   ветку напрямую и до редиректа не доходит.
3. Локально: `git branch -u origin/main`, `git remote set-head origin -a`,
   затем `git push origin main`, `6a90afb..42af42d`, fast-forward.

## Проверено после

- Все 17 картинок README 1.2.1 по старым адресам с параметром против кеша: 16
  `image/png` и 1 `image/jpeg`. Ссылка на папку `example` отдаёт HTML, так
  и должна.
- Новый адрес из README в дереве, `blob/main/…?raw=true`, отдаёт `image/png`.
- На странице пакета на pub.dev все 17 картинок через прокси отвечают `200`.
  Из кеша прокси или из источника, снаружи не различить; источник отвечает
  картинкой в любом случае.
- CI ловит только `main` (`.github/workflows/ci.yml`), поэтому `master` его
  не запускает.

## Чего ветка требует

`master` больше не двигается и не удаляется: на ней держатся картинки README
изданных версий на pub.dev и в форках. Правило записано в `AGENTS.md`,
раздел 8. Релизы, начиная со следующего, ссылаются на `main`.

Сверено по тегам: README 1.1.9, 1.1.9+1, 1.2.0 и 1.2.1 ссылаются на 17 файлов,
и все они в `6a90afb` есть. У 1.1.6 и 1.1.8 картинки сломаны ещё
до переименования: `screenshots/screenshot_10.png` … `screenshot_190.png`
удалены из ветки раньше 1.2.1, и замороженная `master` их не вернёт. Версии без
тегов (на pub.dev их от 0.0.1 до 1.1.8+2) не проверялись.

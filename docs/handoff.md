## Решения владельца

2026-10-15, по итогам реанимации:

- **коммитить** — сделано, схема коммитов предложена агентом;
- **ветку `master` переименовать** (в `main`, как у соседей) — локально
  сделано: ветка, CI, `AGENTS.md`, ссылки README на `blob/main/…`. На GitHub
  не сделано, см. ниже;
- **Д1 и Д2 чинить** — отдельными `fix:`-коммитами; версия не названа, поэтому
  в `## Unreleased` без бампа.

Не решено: **push** и первый прогон CI. Переименование ветки на GitHub — тоже
действие на GitHub, оно ждёт того же слова, и у него есть цена.

**Переименование на GitHub ломает картинки в старых README.** Проверено
2026-10-15 на dart-lang/sdk, где `master` уже переименована в `main`: ссылка
`github.com/…/blob/master/<png>?raw=true` уходит редиректом
на `blob/main/<png>` без `?raw=true` и отдаёт HTML-страницу (`text/html`);
та же ссылка на `main` доходит до `raw.githubusercontent.com` и отдаёт
`image/png`. Все 18 скриншотов README 1.2.1 — ссылки вида
`blob/master/…?raw=true`, и pub.dev показывает их через свой прокси
`external-images.pub.dev`, который ходит по этому адресу. После переименования
скриншоты пропадут со страницы пакета на pub.dev до следующего релиза (README
в дереве уже ссылается на `main`), а на страницах старых версий и в README
форков — насовсем. Варианты:

1. переименовать и вскоре выпустить релиз;
2. после переименования завести замороженную `master` на `6a90afb` — тогда
   старые ссылки найдут ветку напрямую, без редиректа (на этом репозитории
   не проверено);
3. на GitHub не переименовывать — тогда вернуть `master` в CI, `AGENTS.md`
   и README.

## Найдено

**Д1. `GlobalKey` на `Bubble` роняет сборку.** `build` передаёт `key` самого
виджета внутреннему `Container` (`lib/bubble.dart`, метод `build`), и ключ
оказывается в дереве дважды. Пробник 2026-10-15 на 3.27.0:
`FlutterError: Multiple widgets used the same GlobalKey.` С обычным `ValueKey`
вреда нет. Появилось в 1.2.1 («Added a key»). Исправление — убрать `key: key`;
видимо только тем, у кого `GlobalKey` сейчас падает.

**Д2. Смена цвета или рамки не перерисовывает пузырь.** `BubblePainter`
и `BubbleClipper` возвращают `false` из `shouldRepaint` и `shouldReclip`
безусловно. Новый painter того же типа с `shouldRepaint == false`
`RenderCustomPaint` не помечает на перерисовку. Пробник: после смены `color`
и после смены `borderColor` у того же пузыря `debugNeedsPaint == false` после
layout. Исправление — сравнивать параметры; форма уже держится снимками,
порядок отрисовки — тестами «Bubble paints».

**Н1. `IssueClipper` — публичная библиотека.** `lib/issue_clipper.dart` нужен
только примеру, но импортируется как `package:bubble/issue_clipper.dart`.
Перенос в `example/` — удаление публичного имени, то есть решение владельца
и запись в CHANGELOG.

**Н2. Демонстрация тени в примере, возможно, устарела.** Блок «The failed
shadow» показывает flutter/flutter#37779, закрытое в 2022-м. На 3.47.0 контуры
`IssueClipper` рисуются без видимого дефекта в тестовом рендере; на устройстве
не проверено. Если обход не нужен, уходят и блок, и url_launcher, и Н1 решается
вместе.

**Н3. Тема примера.** `ThemeData(primarySwatch: Colors.teal)` при Material 3
по умолчанию (с Flutter 3.16) шапку в бирюзовый не красит — пример выглядит
не так, как на скриншотах README. Косметика.

**Н4. Последний пузырь примера** подписан `'dsfdfdfg'` — тестовая строка
автора, на витрине Example на pub.dev выглядит мусором.
